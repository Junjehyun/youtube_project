# 캔바 → 파이썬 파이프라인 전환 계획

기존에 Canva로 수작업하던 "숫자/한자 찾기" 숏츠 제작을, 본 프로젝트(Python 자동 생성 파이프라인)로 대체하기 위한 분석 및 설계 문서.

---

## 1. 현재 방식(Canva) 분석

레퍼런스로 받은 `260831-2.mp4`를 프레임 단위로 확인한 결과:

- 1080×1920, 10초, **정적 이미지 1장 + 오디오 트랙**으로만 구성 (애니메이션·정답 공개 없음)
- 구조: 네온 타이틀 배너(`숨은 174를 찾아라!`) → 서브텍스트(`10초 이내에 찾으면 뇌가 젊습니다`) → 175로 채워진 8×N 격자 안에 174 하나
- **실제 발견된 문제**: 격자 안에 `174` 외에 `387`이라는 두 번째 이상값이 섞여 있음. "174를 찾아라"가 문제인데 정답이 아닌 숫자가 하나 더 다르게 들어간 것 — 사람이 캔바에서 숫자를 하나하나 타이핑/배치하다가 발생한 실수로 보임.

즉 현재 워크플로우는 매번:
1. 캔바에서 격자 텍스트 박스를 열고 숫자를 수작업으로 채움
2. 정답 위치 하나를 수동으로 다른 값으로 바꿈
3. 배경음/타이머 효과음을 수동으로 붙임
4. mp4로 내보내기
5. 유튜브에 수동 업로드

를 반복하는 구조이고, 사람이 개입하는 단계마다 실수(위 `387` 사례)가 들어갈 여지가 있음.

## 2. Canva 대비 이 파이프라인의 장점

| 항목 | Canva (현재) | Python 파이프라인 |
|---|---|---|
| 격자 생성 | 손으로 숫자 하나하나 배치 | `numpy`로 좌표/값 랜덤 생성 → 오탈자·중복 이상값 원천 차단 |
| 정답 보장 | 육안 검수 (실수 발생: `387` 사례) | 코드로 "이상값은 정확히 1개"를 강제 → 검수 불필요 |
| 반복 생산 | 영상 1개당 반복 수작업 | 데이터(문제 세트)만 바꾸면 동일 로직으로 대량 생성 |
| 요일별 포맷 변경 | 템플릿을 매번 새로 손봄 | 포맷별 모듈만 교체 (아래 3장) |
| 텍스트 다국어/폰트 | 수동 폰트 적용 | `assets/fonts/`에 등록한 폰트로 코드에서 일괄 적용 |
| 업로드 | 수동 로그인 후 업로드 | `google-api-python-client`로 예약 업로드 자동화 가능 |
| 재현성 | 파일 유실 시 복구 불가 | 코드+데이터로 언제든 동일 결과 재생성, git으로 버전 관리 |
| 확장성 | 새 효과 추가 시 템플릿 재작업 | TTS(edge-tts)·효과음(pydub) 등 코드 레벨에서 조합만 추가 |

핵심은 "매번 손으로 만드는 것"에서 "요일별 설정값만 바꾸면 파이프라인이 알아서 찍어내는 것"으로 바뀌는 것.

## 3. 요일별 콘텐츠 캘린더

사용자가 지정한 업로드 스케줄:

| 요일 | 영상 | 이유 |
|---|---|---|
| 월·수·금 | 기존 숫자찾기 | 이미 1~3천 조회 검증됨 |
| 화 | 한자 하나 찾기 (未/末) | 댓글 테스트 |
| 목 | 何個ある？ | 댓글이 숫자로 나오는지 확인 |
| 토 | 2단 퀴즈 15초 | 시청시간 테스트 |

각 요일 포맷을 파이프라인 관점에서 뜯어보면:

- **월·수·금 — 숫자찾기**: 기존에 검증된 로직 그대로. N×M 격자에 기본값(예: 175) 채우고 무작위 좌표 1곳만 다른 값(174)으로 치환. 리스크가 가장 낮으므로 자동화 1순위.
- **화 — 한자 하나 찾기 (未/末)**: 격자의 값이 숫자가 아니라 한자 1글자. 서로 헷갈리기 쉬운 한자 쌍(未/末, 土/士 등)을 데이터로 등록해두고 그중 하나를 기본값, 다른 하나를 이상값으로 사용. 일본어 폰트가 숫자용 폰트와 다를 수 있어 `assets/fonts/`에 별도 등록 필요. "댓글 테스트"이므로 정답을 영상 내에 공개하지 않고 댓글 유도 문구를 넣는 것이 포인트.
- **목 — 何個ある？**: "찾아서 위치를 짚는" 문제가 아니라 "특정 대상이 총 몇 개 있는지 세는" 문제. 격자 생성 로직은 비슷하지만 이상값이 1개가 아니라 N개(랜덤 개수) 섞여야 하고, 그 N이 정답이 됨. 댓글에 달리는 숫자가 실제 정답과 얼마나 일치하는지 확인하는 게 목적이므로, 정답 개수를 코드에서 확정적으로 관리(문제 생성 시점에 로그로 남김)하는 게 중요.
- **토 — 2단 퀴즈 15초**: 한 영상 안에 문제 2개를 순차 배치(예: 5초+5초+여백, 또는 7~8초씩). 이미지 1장이 아니라 2개의 정지 이미지를 순서대로 이어붙이는 영상 합성이 필요 — MoviePy에서 `concatenate_videoclips`로 두 `ImageClip`을 이어 붙이면 됨. 시청시간(retention) 테스트가 목적이므로 두 번째 문제가 나오기 전까지 이탈을 막는 훅(예: "다음 문제도 있어요") 문구 배치가 중요.

## 4. 파이프라인 아키텍처 (흐름도)

```
[1] 콘텐츠 캘린더 설정
    (요일 → 포맷 매핑: 위 표)
        │
        ▼
[2] 문제 데이터 생성 (data/*.json)
    - 포맷별 생성기가 담당
      · 숫자찾기: 기본값/이상값/격자 크기
      · 한자찾기: 기본 한자/이상 한자 쌍
      · 何個ある: 기본값 + 이상값 등장 횟수(N)
      · 2단 퀴즈: 문제 2세트
    - 이 단계에서 "정답"이 로그로 확정됨 (수작업 검수 불필요)
        │
        ▼
[3] 이미지 렌더링 (Pillow, src/render_*.py)
    - 배경 + 타이틀 배너 + 격자 텍스트 그리기
    - 폰트: assets/fonts/
        │
        ▼
[4] 오디오 준비
    - assets/bgm/ (긴장감 배경음), assets/sfx/ (타이머·효과음)
    - 필요 시 edge-tts로 문제 안내 음성 합성
        │
        ▼
[5] 영상 합성 (MoviePy)
    - 단일 이미지 포맷: ImageClip + 오디오
    - 2단 퀴즈 포맷: 이미지 2개 concatenate + 오디오
        │
        ▼
[6] 출력 (output/YYMMDD-N.mp4)
    - 기존 파일명 규칙(260831-2.mp4 등) 그대로 유지
        │
        ▼
[7] (자동화 단계) 유튜브 업로드
    - google-api-python-client + OAuth(client_secret.json)
    - 요일별 캘린더에 맞춰 예약 게시 시간 지정
        │
        ▼
[8] 결과 로그 적재
    - 어떤 영상에 어떤 정답/포맷을 썼는지 data/에 기록
    - 화·목 요일 댓글 테스트 결과를 나중에 이 로그와 비교 가능
```

## 5. "자동화해서 편하게" — 실행 방식 제안

1. **1단계(지금 당장)**: 3장의 포맷 4종 중 리스크가 가장 낮은 "숫자찾기"부터 `[2]→[5]` 코드를 완성해서 기존 검증 포맷을 자동 생성으로 대체.
2. **2단계**: 매일 자정 등 정해진 시각에 스크립트를 실행해 그날 요일에 맞는 포맷으로 문제 데이터 생성 + 렌더링까지 자동 수행 (macOS `launchd` 또는 간단한 cron으로 스케줄링).
3. **3단계**: 생성된 mp4를 사람이 최종 1회 검수(썸네일/문구 확인)한 뒤, 업로드만 승인하는 반자동 방식으로 시작 — 처음부터 업로드까지 전자동화하면 문제 있는 영상이 그대로 올라갈 리스크가 있으므로, 검수 단계는 당분간 남겨두는 걸 권장.
4. **4단계**: 화·목 포맷의 댓글 테스트 결과가 쌓이면, 업로드까지 완전 자동화(무인 스케줄 게시)로 전환.
